## 第二章 软件概述

### 2.1 开发背景及意义

微生物学和细胞生物学实验中的人工计数方式效率低、主观误差大，尤其在处理大批量样本或高密度菌落/细胞图像时，人工计数结果的一致性难以保证。本软件结合视觉语言模型与传统数字图像处理算法，实现菌落与细胞的自动检测计数，并提供人工修正手段，兼顾自动化效率与结果可靠性。

### 2.2 软件目标

1. 提高菌落和细胞计数的效率与准确性；
2. 降低人工计数的主观误差和工作强度；
3. 提供可视化、可交互的计数结果修正手段；
4. 支持结构化结果导出，便于后续数据分析；
5. 提供标准化的对外接口，便于与其他实验室信息系统集成。

### 2.3 总体功能列表

| 功能模块 | 说明 |
|----------|------|
| 菌落计数 | 自适应两阶段检测策略，按密度分层处理，输出菌落数量与坐标 |
| 细胞计数 | 基于视觉语言模型的细胞检测，支持框选局部区域和多种推理模式 |
| 交互式修正 | 支持手动添加/删除标记点、多步撤销、一键重置 |
| 结果导出 | 支持导出 CSV 格式结果文件 |
| 对外接口 | 提供 RESTful API，支持第三方系统集成 |

### 3.2 技术路线

#### 3.2.1 菌落计数技术路线

菌落计数采用**传统图像处理 + 深度学习**相结合的混合方案：

1. **图像预处理**：使用 CLAHE 增强图像对比度，突出菌落与背景的差异；
2. **模型粗定位**：将图像送入 LocateAnything-3B 模型，获取候选菌落的边界框；
3. **密度分析**：根据候选框数量判断菌落密度，分为稀疏、中等、密集三个等级；
4. **分层处理**：稀疏区域直接使用检测结果；中等密度区域对每个候选框局部增强后重新检测；密集区域使用分水岭算法分割粘连菌落；全图模式对整图进行增强处理；
5. **后处理**：非极大值抑制（NMS）去除重复框，中心距离去重保证每个菌落只计数一次。

#### 3.2.2 细胞计数技术路线

细胞计数采用**纯深度学习**方案：

1. **区域选择**：用户可框选感兴趣区域（ROI），系统裁剪该区域；
2. **模型推理**：将图像（或裁剪区域）送入 LocateAnything-3B 模型，使用细胞检测专用提示词；
3. **结果解析**：解析模型输出的边界框坐标；
4. **NMS 过滤**：使用非极大值抑制去除重叠框；
5. **中心点提取**：计算每个边界框的中心点作为细胞位置。

### 3.4 核心处理流程图

#### 3.4.1 菌落计数处理流程（自适应两阶段决策逻辑）

```
                        ┌──────────────────────┐
                        │  上传图像 / 读取参数   │
                        └──────────┬───────────┘
                                   ▼
                 ┌───────────────────────────────────┐
                 │ 阶段一：原始图像粗定位（模型推理）   │
                 │ worker.predict(原图, 菌落提示词)    │
                 │ → parse_boxes → NMS → 候选框数 N   │
                 └──────────────────┬──────────────────┘
                                    ▼
                  ┌──────────────────────────────────┐
                  │ 判断：N=1 且该框面积 > 80% 图像面积 ?│
                  └───────┬───────────────────┬────────┘
                     是    │                   │  否
                           ▼                   ▼
        ┌───────────────────────────┐   ┌─────────────────────────────┐
        │ 全图框兜底分支              │   │ 按候选框数量 N 判定密度等级   │
        │ CLAHE 增强 + 重新检测       │   └───────────────┬─────────────┘
        │ 仍为全图框？                │                   │
        │  是→ 全图分水岭兜底分割     │      ┌────────────┼────────────┐
        │  否→ 质心计算 + 中心距离去重│      ▼            ▼            ▼
        └───────────────────────────┘  N<稀疏阈值   稀疏阈值≤N<密集阈值  N≥密集阈值
                                        （稀疏）      （中等）         （密集）
                                            │            │                │
                                            ▼            ▼                ▼
                                    直接使用阶段一   CLAHE 增强+重新检测  CLAHE 增强+重新检测
                                    检测结果+质心   +质心计算+中心距离   +分水岭分割大框
                                    精修            去重                +中心距离去重
                                            │            │                │
                                            └────────────┴────────┬───────┘
                                                                   ▼
                                                    ┌───────────────────────────┐
                                                    │ 输出：count/raw_count/stage │
                                                    │ /boxes/centers 结果字典     │
                                                    └───────────────────────────┘
```

## 第四章 模块与函数设计

### 4.1 前端交互模块

前端页面（`index.html`）通过原生 JavaScript 实现标签页切换、图片上传（点击/拖拽）、参数面板展开/收起、Canvas 画布绘制与交互（缩放、平移、标点、框选）、请求后端接口并渲染返回结果。核心状态维护在 `state` 对象中，按 `colony`/`cell` 两个键分别保存各自的图片、标记点列表、缩放比例（`zoom`）、平移偏移量（`panX`/`panY`）、操作历史（`history`，用于撤销）以及交互模式（`interactionMode`，细胞计数专用）。

前端核心函数如下：

| 函数名称 | 功能说明 |
|----------|----------|
| `loadImage` | 将用户选择/拖拽的图片文件读取为可绘制的 `Image` 对象，返回 Promise |
| `showLoading` | 显示/隐藏加载遮罩层，并展示当前处理阶段的提示文字 |
| `showInfo` | 在信息显示区展示成功提示（如检测阶段、原始检测数、最终计数） |
| `showError` | 在信息显示区展示错误提示 |
| `deepCopyPoints` | 深拷贝当前标记点数组，用于生成撤销历史快照 |
| `getCanvasDisplayScale` | 计算画布实际渲染尺寸与逻辑像素尺寸之间的比例 |
| `getCanvasCoords` | 将鼠标事件坐标转换为图像像素坐标（综合考虑缩放和平移偏移） |
| `drawCanvas` | 核心绘制函数，按当前缩放/平移状态重绘图像、标记点（红/绿）及框选虚线矩形 |
| `getImageBase64` | 将当前画布图像导出为 Base64，用于向后端提交裁剪区域等场景 |
| `computeFitZoom` | 根据画布容器尺寸计算"适应"模式下应使用的缩放比例 |
| `updateButtonStates` | 根据当前是否有图片、是否有标记点、历史记录是否为空，更新按钮的可用/禁用状态 |
| `countColony` | 触发菌落计数请求：显示加载提示"正在进行菌落计数..."→提交图片与参数→接收响应并调用 `drawCanvas` |
| `countCell` | 触发细胞计数请求：显示加载提示"正在进行细胞计数..."→（如有框选）提交裁剪坐标→接收响应并渲染 |
| `exportResults` | 将当前标记点数组转换为 CSV 文本（含 UTF-8 BOM），生成下载链接并触发下载 |
| `setupType` | 为指定类型（colony/cell）绑定全部事件监听器，包括上传、鼠标交互、缩放、撤销、重置等 |

前端交互设计要点：

- **标点判定**：鼠标抬起时，若距离已有标记点的像素距离小于 `CLICK_THRESHOLD / 当前缩放比例`（`CLICK_THRESHOLD` 常量取值 15），则判定为点击该标记点并删除；否则在该位置新增一个手动标记点（`source: 'manual'`）。每次增删前都会将当前点集合压入 `history` 栈，供撤销使用；
- **框选判定**：仅在细胞计数、`interactionMode === 'select'` 时生效，拖拽结束后若矩形宽或高小于 5 像素则视为无效框选并清除；
- **缩放范围**：通过 `Ctrl/Cmd + 滚轮` 或工具栏按钮调整，缩放比例限制在 0.1～10 之间，滚轮缩放系数为 1.15，按钮缩放系数为 1.2，且以鼠标位置为中心进行等比缩放；
- **平移方式**：切换平移模式后拖拽画布容器的滚动条位置，或直接使用鼠标中键拖拽。

### 4.3 模型推理层

模型推理层由 `locateanything_worker.py` 中的 `LocateAnythingWorker` 类实现，封装 LocateAnything-3B 模型的加载与多种视觉任务推理：

| 函数名称 | 类型 | 功能说明 |
|----------|------|----------|
| `__init__` | 构造方法 | 加载分词器（Tokenizer）、处理器（Processor）与模型权重，绑定运行设备（GPU）及计算精度（默认 bfloat16） |
| `predict` | 方法 | 核心推理入口：构造多模态对话消息→应用聊天模板→处理器编码图像和文本→调用模型 `generate`→根据 `generation_mode`（fast/slow/hybrid）选择解码策略→返回模型输出文本及可选的耗时统计 |
| `detect` | 方法 | 按给定类别列表构造检测提示词（以 `</c>` 连接多个类别）并调用 `predict` |
| `ground_single` | 方法 | 单目标短语定位，构造"定位单个匹配实例"提示词 |
| `ground_multi` | 方法 | 多目标短语定位，构造"定位所有匹配实例"提示词，菌落/细胞计数底层调用的即为此类提示词模式 |
| `ground_text` | 方法 | 文本内容定位 |
| `detect_text` | 方法 | 图像中文本区域检测 |
| `ground_gui` | 方法 | GUI 元素定位（支持框或点两种输出格式，本软件未直接使用，属于模型通用能力） |
| `point` | 方法 | 点定位任务封装 |
| `parse_boxes` | 静态方法 | 解析模型输出的 `<box><x1><y1><x2><y2></box>` 标签，将 0-1000 归一化坐标换算为像素坐标边界框 |
| `parse_points` | 静态方法 | 解析模型输出的点坐标标签为像素坐标点 |

`predict` 方法的关键实现细节：调用 `model.generate` 时传入 `pixel_values`、`input_ids`、`attention_mask`、`image_grid_hws` 等张量，并设置 `max_new_tokens=2048`、`do_sample=True`、`top_p=0.9`、`repetition_penalty=1.1` 等采样参数；`generation_mode` 参数控制底层解码策略在多 Token 并行解码（MTP，对应 `fast`）与标准自回归解码（NTP，对应 `slow`）之间切换，`hybrid` 模式由模型内部结合两者。

### 4.4 菌落计数算法模块

菌落计数算法模块由 `colony_count_adaptive.py` 实现，核心函数与类如下：

| 函数/类名称 | 类型 | 功能说明 |
|-------------|------|----------|
| `preprocess_image` | 函数 | 在 LAB 颜色空间对图像的亮度通道进行 CLAHE 对比度增强，处理后转换回 RGB，保留原始色彩 |
| `nms` | 函数 | 基于 IoU 的非极大值抑制：按候选框面积从大到小排序，逐一保留并抑制与其 IoU 超过阈值的框 |
| `parse_boxes` | 函数 | 解析模型输出文本中的 `<box>` 标签为像素坐标边界框 |
| `dedup_by_center_distance` | 函数 | 基于中心点欧氏距离去重：按面积从大到小排序，若候选框中心与已保留框中心距离小于阈值则视为重复并剔除 |
| `_compute_region_centroid` | 函数 | 对候选框区域做 Otsu 二值化后计算灰度质心（`cv2.moments`），失败时退化为几何中心 |
| `watershed_split_large_boxes` | 函数 | 对面积超过中位数面积 `area_factor` 倍且绝对面积达到中位数 1.5 倍的候选框，执行局部分水岭分割 |
| `full_image_watershed` | 函数 | 全图分水岭兜底处理，用于模型两次检测均返回覆盖全图单一大框的极端情形 |
| `AdaptiveColonyCounter` | 类 | 自适应菌落计数器，封装模型实例（或接收外部共享实例）与完整计数流程 |
| `AdaptiveColonyCounter.count_colonies_adaptive` | 方法 | 核心方法，实现第 3.4.1 节所述的两阶段自适应决策流程，返回包含 `count`/`raw_count`/`stage`/`boxes`/`centers` 等字段的结果字典 |
| `AdaptiveColonyCounter._boxes_to_centers` | 静态方法 | 将边界框列表转换为中心点列表，优先使用质心坐标（`center_x`/`center_y`），否则使用几何中心 |
| `visualize_centers` | 函数 | 将检测中心点绘制到图像上，用于命令行批处理场景的结果可视化 |
| `process_single_image` / `process_directory` / `main` | 函数 | 命令行独立运行入口，支持单图/批量图像处理，便于脱离 Web 界面进行批量验证 |

**`count_colonies_adaptive` 详细执行步骤**：

1. 对原始图像执行阶段一粗定位：调用 `worker.predict` 传入增强版菌落检测提示词，解析结果并执行 NMS，得到候选框数量 `n_raw`；
2. 判断是否为"全图单一大框"退化情形（`n_raw == 1` 且该框面积超过图像总面积的 80%）；若是，则进入全图框兜底分支：先做 CLAHE 增强后重新检测，若仍为全图大框则调用 `full_image_watershed` 做兜底分割，否则计算各候选框质心并做中心距离去重；
3. 若非退化情形，按 `n_raw` 与 `sparse_threshold`、`dense_threshold` 的比较结果分流：
   - **稀疏**（`n_raw < sparse_threshold`）：直接复用阶段一候选框，仅补充质心精修，不再调用模型二次推理，以节省耗时；
   - **中等**（`sparse_threshold ≤ n_raw < dense_threshold`）：对整图做 CLAHE 增强后重新推理，计算候选框质心，执行中心距离去重；
   - **密集**（`n_raw ≥ dense_threshold`）：在中等分支的基础上，额外调用 `watershed_split_large_boxes` 对面积异常偏大的候选框进行分水岭拆分，再执行中心距离去重；
4. 统一将最终候选框集合转换为中心点列表（`_boxes_to_centers`），连同 `count`、`raw_count`、`stage`（处理阶段标识）、`boxes`、`centers`、模型原始输出文本一并返回。

**`watershed_split_large_boxes` 详细执行步骤**（对判定为"大框"的候选框执行）：

1. 以候选框边界向外扩展 5 像素作为局部区域，裁剪出该区域的灰度图；
2. 对局部区域做 CLAHE 对比度增强（`clipLimit=2.0`，网格 8×8），再做 Otsu 自适应二值化（反色）；
3. 对二值图做形态学开运算（去除细小噪点）和闭运算（填补小孔洞）；
4. 对处理后的二值图做欧氏距离变换，取距离图最大值的 `dist_threshold_ratio` 倍作为阈值提取"确定前景"种子区域；
5. 对二值图做膨胀得到"确定背景"区域，用背景减去前景得到"未知区域"；
6. 对前景种子做连通域标记，未知区域标记为 0，调用 `cv2.watershed` 从种子点向外扩展完成分割；
7. 遍历各分割标签，过滤面积小于 `min_split_area_ratio × 图像总面积` 的碎片区域，其余区域计算质心坐标并映射回原图坐标系，作为拆分后的子候选框返回；若分割结果为空，则回退为使用原候选框的质心。

### 4.5 细胞计数算法模块

细胞计数算法模块由 `count_simple.py` 实现：

| 函数名称 | 类型 | 功能说明 |
|----------|------|----------|
| `nms` | 函数 | 基于 IoU 的非极大值抑制，去除重叠的细胞检测框，逻辑与菌落模块的 `nms` 一致 |
| `parse_boxes` | 函数 | 解析模型输出文本为像素坐标边界框 |
| `visualize_result` | 函数 | 将检测框/中心点绘制到图像上，用于命令行批处理场景的结果可视化 |

## 第六章 算法设计

### 6.1 图像预处理（CLAHE 对比度增强）

CLAHE（Contrast Limited Adaptive Histogram Equalization，对比度受限自适应直方图均衡化）将图像划分为若干网格子区域，分别进行直方图均衡化，并通过对比度限制参数防止过度增强噪声。本软件在 LAB 颜色空间的亮度通道上应用 CLAHE，以保留图像原始色彩。关键参数：

- **对比度限制（clip_limit）**：默认 2.0，可调范围 0.5-10.0，值越大增强越强，但可能放大噪声；
- **网格大小（tile_grid_size）**：默认 8，可调范围 4-16，将图像划分为 tile_grid_size × tile_grid_size 个子区域。

算法步骤（伪代码）：

```
function preprocess_image(image, clip_limit, tile_size):
    rgb ← 转为 RGB 数组
    lab ← RGB 转 LAB 颜色空间
    L, A, B ← 拆分 LAB 三通道
    clahe ← 创建 CLAHE(clipLimit=clip_limit, tileGridSize=(tile_size, tile_size))
    L_enhanced ← clahe.apply(L)
    lab_enhanced ← 合并(L_enhanced, A, B)
    result ← LAB 转回 RGB
    返回 result
```

### 6.2 模型推理策略（LocateAnything-3B 目标检测）

LocateAnything-3B 是 NVIDIA 开发的视觉语言模型，通过构造特定提示词（Prompt）引导模型输出目标的边界框坐标，坐标以 `<box><x1><y1><x2><y2></box>` 标签形式输出，取值范围为 0-1000 的归一化整数，需按图像实际宽高换算为像素坐标。本软件调用其推理接口时支持三种解码模式：

- **fast（MTP 模式）**：多 Token 并行解码（Multi-Token Prediction），单步可生成多个候选 Token，速度最快，适合大批量处理；
- **slow（NTP 模式）**：标准自回归解码（Next-Token Prediction），逐 Token 生成，精度最高，适合精细检测；
- **hybrid（混合模式）**：结合 MTP 和 NTP 两种解码方式，兼顾速度与精度（默认）。

菌落检测使用增强提示词（`ENHANCED_PROMPT`），显式要求模型将相互粘连/重叠的菌落分别框选、不得合并为一个大框，并要求统计边缘处的部分可见菌落；细胞检测使用专用提示词（`CELL_PROMPT`），描述细胞在拥挤时可能呈现为椭圆或半圆形状，同样要求逐一独立框选。

### 6.3 自适应密度分层策略

菌落计数模块根据初步检测结果中的候选框数量，自动选择处理策略：

| 密度等级 | 候选框数量 | 处理策略 |
|----------|------------|----------|
| 稀疏 | < sparse_threshold | 直接使用模型检测结果 + 质心精修 |
| 中等 | sparse_threshold ~ dense_threshold | 对整图局部增强后重新检测 + 中心距离去重 |
| 密集 | ≥ dense_threshold | 增强后重新检测 + 分水岭分割 + 中心距离去重 |

若二次检测后仍出现候选框覆盖整幅图像的极端情况（面积占比 > 80%），则触发全图分水岭兜底处理，使用纯传统图像处理算法（CLAHE + Otsu 二值化 + 距离变换 + 分水岭）分割整幅图像。用户可通过调节 `sparse_threshold` 和 `dense_threshold` 参数，适应不同实验条件下的菌落密度分布。

### 6.4 非极大值抑制（NMS）与中心距离去重

**非极大值抑制（NMS）**：计算所有候选框两两之间的 IoU（交并比），按面积从大到小排序后保留框，抑制与已保留框 IoU 超过阈值的框。本软件中 NMS 的 IoU 阈值默认 0.3，可调范围 0.1-0.9。算法步骤：

```
function nms(boxes, iou_threshold):
    为每个 box 计算 area
    按 area 降序排序 boxes
    keep ← []
    while boxes 非空:
        current ← boxes 中面积最大者（弹出）
        keep.append(current)
        boxes ← boxes 中与 current 的 IoU < iou_threshold 的框
    返回 keep
```

**中心距离去重**：在密集场景下，重叠菌落的 IoU 可能依然很高，仅用 IoU 去重容易误删相邻的独立菌落。因此在 NMS 之后，进一步按候选框面积从大到小排序，依次检查候选框中心点与已保留中心点的欧氏距离，若小于 `dedup_distance`（默认 3.0 像素）则视为重复，予以剔除。中心点优先使用区域灰度质心（`_compute_region_centroid`），在无法计算质心时退化为边界框几何中心。

### 6.5 分水岭分割算法（密集菌落拆分）

对于密集区域中面积明显偏大的候选框（可能是多个粘连菌落被识别为一个大框，判定条件为面积超过所有候选框面积中位数的 `watershed_area_factor` 倍且绝对面积超过中位数的 1.5 倍），本软件使用分水岭（Watershed）算法进行分割：

1. 对大框区域（外扩 5 像素）进行局部 CLAHE 增强；
2. 对增强后的灰度图执行 Otsu 自适应二值化（反色），并做形态学开、闭运算去噪；
3. 使用距离变换计算每个前景像素到最近背景像素的距离；
4. 取距离图最大值的一定比例作为阈值，筛选出"确定前景"作为分割种子点；
5. 对二值图膨胀得到"确定背景"，两者相减得到"未知区域"；
6. 对种子区域做连通域标记，未知区域标记为 0，调用分水岭算法从种子点向外扩展，分割出各个独立区域；
7. 过滤面积过小的分割碎片，其余区域计算质心作为该子菌落的中心坐标。

关键参数：

- **watershed_area_factor**：判定"大框"的面积阈值因子，默认 2.0；
- **watershed_dist_ratio**：距离变换阈值比例，用于筛选有效种子点，默认 0.3；
- **watershed_min_area_ratio**：分割后子区域的最小面积比例，过小的区域将被过滤，默认 0.0005。

## 第七章 异常处理与性能设计

### 7.1 异常处理设计

后端各计数路由函数（`colony_count`、`cell_count` 等）均使用 `try / except / finally` 结构包裹核心逻辑：

- **图像解码异常**：`decode_image_file` 在图像格式无效时抛出 `HTTPException(400)`，提示"图片格式无效"；
- **推理/算法异常**：计数路由函数捕获所有异常，打印完整堆栈（`traceback.print_exc()`），并向前端返回 `{"success": false, "error": "...", "count": 0, "points": [], "image_base64": null}` 的统一错误结构，HTTP 状态码为 500；
- **资源释放兜底**：无论请求成功还是异常，`finally` 块中均调用 `cleanup_cuda_memory()` 释放显存缓存，避免异常场景下的显存泄漏累积；
- **前端容错**：前端 `countColony`/`countCell` 函数对请求异常（网络错误等）单独捕获，通过 `showError` 展示"请求失败: ..."提示，不会导致页面崩溃。

### 7.2 性能与资源设计

- **图像尺寸限制**：`limit_image_size` 将上传图像最大边长限制在 2048 像素以内（等比例缩放），在保证检测精度的同时控制显存占用和推理耗时；
- **模型单例复用**：`get_shared_worker`、`get_colony_counter` 采用全局变量 + 延迟初始化模式，模型仅在首次请求时加载一次，菌落计数与细胞计数共用同一个 `LocateAnythingWorker` 实例，避免重复加载模型带来的显存浪费和启动延迟；
- **显存及时释放**：每次推理请求结束后主动调用 `torch.cuda.empty_cache()` 并打印已分配/已保留显存量，便于运维监控及问题定位；
- **稀疏场景免二次推理**：自适应密度分层策略在"稀疏"档位下直接复用阶段一检测结果，避免不必要的二次模型调用，降低平均响应耗时；
- **分阶段解码模式**：细胞计数支持 fast/slow/hybrid 三种解码模式，允许用户按精度和耗时的实际需求权衡选择。

## 第九章 运行环境与部署设计

### 9.1 运行环境要求

| 硬件 | 最低要求 | 推荐配置 |
|------|----------|----------|
| GPU | NVIDIA GPU，显存 ≥ 8GB | NVIDIA GPU，显存 ≥ 12GB |
| 内存 | 16GB | 32GB |
| 磁盘 | 20GB（含模型文件） | 50GB（含缓存和结果文件） |
| CPU | 多核处理器 | 4核及以上 |

操作系统推荐 Ubuntu 20.04 / 22.04 LTS，或其他支持 CUDA 的 Linux 发行版；Windows 平台需通过 WSL2 提供 CUDA 支持。

### 9.2 部署方式

1. 创建独立的 Python 虚拟环境，隔离依赖版本；
2. 通过 `requirements.txt` 及额外命令安装 PyTorch、transformers、accelerate、FastAPI、uvicorn 等依赖；
3. 将 LocateAnything-3B 模型文件置于项目根目录下的固定路径，供 `LocateAnythingWorker` 加载；
4. 使用 `run_fastapi.sh` 脚本或手动执行 `uvicorn main:app --host 0.0.0.0 --port 8000` 启动服务，服务同时对外提供 API 接口和前端静态页面；
5. 部署完成后，通过浏览器或 API 客户端访问 `http://<服务器地址>:8000` 使用本软件。

### 9.3 目录结构设计

```
locateanthing_colony_count/
├── LocateAnything-3B/                 # 模型权重文件
├── Eagle/Embodied/
│   └── locateanything_worker.py       # 模型推理层
├── colony_count_adaptive.py           # 菌落计数算法模块
├── count_simple.py                    # 细胞计数算法模块
└── colony_cell_gui_fastapi/
    ├── frontend/
    │   └── index.html                 # 前端交互模块
    ├── backend/
    │   ├── main.py                    # 后端服务模块
    │   └── requirements.txt           # 依赖清单
    ├── uploads/                       # 上传图片缓存目录（运行时自动创建）
    ├── results/                       # 结果图片缓存目录（运行时自动创建）
    └── run_fastapi.sh                 # 启动脚本
```

## 附录 术语表

| 术语 | 说明 |
|------|------|
| CLAHE | 对比度受限自适应直方图均衡化，一种局部对比度增强算法 |

| ROI | 感兴趣区域，指用户框选希望重点分析的图像局部区域 |

| NTP | 标准自回归逐 Token 解码，模型精细推理模式 |
| 分水岭算法 | 一种基于图像形态学和距离变换的区域分割算法，常用于分割粘连目标 |
| 质心 | 区域内像素灰度加权后的几何中心，用于更精确地定位目标中心坐标 |
